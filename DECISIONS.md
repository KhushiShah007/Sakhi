# Decisions

- **Built on the existing Vite prototype** (the brief allows building on the prototype's design system) instead of rewriting to Next.js. Re-evaluate when the API lands; Fastify is the planned API.
- **Safety core is pure TypeScript with no I/O** so it is unit-testable and reusable by app, WhatsApp and IVR channels.
- **Zod v4**; `z.partialRecord` for MRS scores.
- **Red flags over-trigger on purpose** (negations like "no chest pain" still trigger). Safe failure direction.
- **Crisis > policy > LLM** ordering; a message with both a jailbreak and self-harm gets the crisis reply.
- **Policy refusals also bypass the LLM.** The brief only requires this for crisis; bypassing here keeps refusals deterministic and testable.
- **Substring regexes, not `\b`,** because word boundaries are unreliable for Devanagari/Gujarati.
- **MRS from logs = max severity per item** in the window (simple, explainable); to be validated clinically.
- **Complementary suppression** hides the next-smallest visible group when exactly one group is suppressed.
- **Dev-only encryption key** is derived deterministically when `SAKHI_DATA_KEY` is unset and `NODE_ENV!=production`; production throws.
- **Tooling gaps in this environment**: no Docker, Postgres or `gh` installed, so DB-backed work could not be verified here.
- **DB**: Postgres dialect via SQL migrations; PGlite (embedded) for dev/tests, `pg` when `DATABASE_URL` is set. Chosen because Docker was unavailable; Prisma dropped for the same reason (revisit if desired).
- **Proposal sets are stored in Postgres, AES-GCM encrypted** (aad = owner + id), 15-min TTL, single use via atomic DELETE...RETURNING; they hold symptom/severity only, never her words. Survives restarts and multiple instances.
- **Crisis replies skip consent and persistence** so help is never withheld and no crisis flag exists anywhere.
- **Audit log stores metadata only**; on account deletion its user_id is replaced by a hashed tombstone so the trail survives without identity.
- **OTP provider** is a generic webhook (`OTP_WEBHOOK_URL`) so any SMS gateway can be plugged in; no vendor SDK baked in.
- **Family link = bearer token in the URL** (24 random bytes, only its hash stored). Unknown, paused and revoked links return the identical 410 so state is not leaked. Rotate/revoke kill the old link immediately.
- **Family text is never composed from her input**: cards are an enum mapped to fixed, localized sentences; `signals` has no text column. Preview and the real family page share one `familyView` function so the preview cannot drift.
- **Teens (role `teen`) are content-only**: no phone stored, never targeted by signals, only the teen module is visible.
- **Her phone-based WhatsApp delivery uses the approved-template route** (needed outside the 24h window); template spec is in `.env.example`/SETUP (to write).
- **Household weather alert shares the risk LEVEL only**, for tomorrow, only with `family_signals` consent and per-person `perm_alerts`. Stress days now come from the persisted, confirmed `trigger` on her logs (migration 004).
- **HUI = understood / delivered cards in the month**, where understood = family replied done AND she later tapped "it helped". Failed deliveries excluded.
- **Time of day and trigger are stored on logs** as fixed vocabularies (never free text); extracted, then confirmed or corrected by her like severity.
- **The API serves the built web app** (same origin) so the family link, cookies and CSRF need no CORS configuration. Hash routes mean only `/` needs `index.html`.
- **Bodyless requests with a JSON content-type are accepted** (treated as no body); malformed JSON is a 400. Browsers and fetch wrappers do this routinely.
- **Revoked/paused links return HTTP 410**; browsers log that as a console error in dev tools, which is expected and intended.
- **"Say it for me" never sends the calm sentence to the family.** The three-tone sentence is for her to play aloud (browser voice) or copy and say herself. The only thing that travels through Sakhi's family channel is the enumerated Signal Card, so "family never sees her words" holds even for rewrites. The card is suggested by rules from her confirmed symptoms and she can change it.
- **Screens that mount two stages do not use AnimatePresence exit waits when a shared-layout child (the tone selector pill) is present**: it left the "sent" screen stuck. Caught by the real-browser test.
- **Live screens only appear when logged in**; demo, screenshots and static hosting keep the scripted screens (`useLive()` + `useEmbedded()` + forced-stage params).
- **PIN lock is enforced on the server**: a locked session gets 423 on everything except `GET /api/me`, `POST /api/pin/verify`, `POST /api/lock`, `POST /api/auth/logout` (matched by method + path; a path-only list once let a locked session delete the account, caught by a test). While locked, `/api/me` reveals nothing about her. A page opened fresh (new tab) is locked; leaving the tab for 60s re-locks it. 5 wrong PINs lock PIN entry for 5 minutes. A 4-digit PIN is a small space: this is a shared-phone deterrent, not strong authentication (see THREAT-MODEL).
- **"Hide in recents" is best effort in a browser**: the page is blanked on blur/hidden, but a web page cannot control what the OS app-switcher snapshots. A native wrapper (Capacitor/TWA with FLAG_SECURE) would be needed for a guarantee.
- **`/api/session` answers 200 even when nobody is signed in** so anonymous pages (login, family link) never log 401s.
- **Deleting the account deletes the family links** (people cascade); the audit trail keeps a hashed tombstone.
- **Brief PDF is English only (Helvetica)**: the doctor copy is always English by spec. Her-language copy is the on-screen view with browser print/save (browsers shape Devanagari/Gujarati correctly; pdfkit without bundled script fonts would not). Bundling Noto fonts into pdfkit is possible later.
- **Doctor links hold a frozen encrypted snapshot**, expire in 7 days, can be revoked, and die when she withdraws `doctor_brief` consent or deletes her account. Unknown, expired and revoked links answer identically (410).
- **Timeline covers 4 x 7 days ending today; MRS covers 30 days.** Max severity per item over the window (explainable, to be validated clinically).
- **PDF page-count bug fixed during visual review**: the count was read after the document flushed (always 0), so the renderer always used its smallest scale. Always look at generated PDFs.
- **Server TTS is optional and additive**: `/healthz` reports `tts: server|browser` (never a key); the client uses the server voice only when told, and any failure drops to the browser voice (once, not twice). Only the app's own wording is voiced; no third-party voice of a real person, premade voice by default. ElevenLabs processes that text: say so in PRIVACY.md and keep the key server-side.
- **Dev database persists by default** (`.data/pglite`, gitignored; `PGLITE_DIR=memory` for a throwaway one). Production still requires `DATABASE_URL`.
- **HR and admin dashboards are English-only** (staff tools). Every employee- and family-facing screen is in all four languages. A known gap against "all UI translated".
- **HR numbers are rounded (counts down to 5, percentages to 5) in addition to k>=10**, so one person joining or leaving does not move a figure. Documented limit: a determined HR analyst watching totals across many small changes can still learn something; THREAT-MODEL.md covers it.
- **Admin console is a review register, not a CMS**: the app serves wording from code. Editing creates an unreviewed *draft* that is not served; only engineering publishes. This keeps "clinician reviewed" truthful (a DB check refuses reviewed=true without reviewer and date).
- **Pilot analytics count only people who consented to research**, separate from the employer opt-in (purpose limitation). Seeded numbers are synthetic and only demonstrate the mechanics.
- (superseded by the Rehearsal chat below) **Rehearsal personas were fixed scripted turns** (realistic, never abusive); feedback judges HER phrasing by rules. An LLM-driven persona was not added.
- **Letter wording never uses "in my voice"**: the Letter reads aloud in the calm synthetic voice (no voice cloning, ever).

## Vent, Rehearsal and voice fixes
- **Vent on static hosting records for real** (chosen over a "demo only" banner). The same safety pipeline (`server/src/safety`: red flags, policy, rule extraction, `confirmEntries`) is imported into the web bundle through `src/offline/engine.ts`; with no API, `/vent` uses the real microphone and her confirmed entries are kept in `localStorage` (`sakhi.local.logs`) with a visible "saved on this device only" note. Crisis phrases still show helplines. The scripted `VentMock` stays only for the embedded demo and forced-stage screenshots. History and Home are not wired to the on-device entries (known gap).
- **Speech recognition language chain**: requested language, then `hi-IN`, then `en-IN`, only when the engine reports `language-not-supported`; the screen says which language is in use. `finish()` waits for `onend` (600 ms cap) so the last final result is not lost; restarts after a pause are capped (more than 4 in 3 s stops with an error); `start()` stays synchronous inside the tap and silences Sakhi's voice first; a non-secure page gets its own message.
- **Level meter** uses `getUserMedia` + `AnalyserNode` for loudness only. Nothing is recorded or sent.
- **Voice never fails silently**: an engine error is no longer "end". `speak()` takes `onError(reason)`; on no voice / error the line is shown as text and the track continues at reading pace (`readingMs`), `useVoiceStatus()` drives a visible note with a link to voice settings. A Marathi line may use a Hindi voice (same script); a Gujarati line has no stand-in, so it is shown as text rather than read by an English voice. Watchdog = `120 ms x characters + 3 s`. One silent utterance on the first tap unlocks mobile audio. Server TTS (when configured) is still tried first.
- **Right Now**: full cue for the first two 12-second cycles only, then one varied encouraging line about every 30 s (4 lines, never the same twice in a row). 90 s now speaks about 10 lines instead of about 22. The relax track ends with "Done" and does not restart; the 3 AM wind-down and the missed-call script each play once. Captions mirror what is spoken.
- **Rehearsal is a chat** with rule-based intents (greeting, shares, request, question, blame, giveup, thanks, other) in hi/mr/gu/en plus Hinglish. Each character moves from resistance to understanding to agreement, never repeats a line, and ends after a clear request (or 8 turns). With `ANTHROPIC_API_KEY` the model plays the character (system prompt per scenario, last ~12 turns, her words in tags as data, output validated: Zod 1-300 chars, right script, output blocklist, not a repeat); anything that fails uses the rules. Crisis phrases (helplines, role-play pauses, turn not stored) and policy violations (no diagnosis or medicine advice) are checked before any reply. Sessions are stored in `rehearsal_sessions` / `rehearsal_turns` (text AES-GCM encrypted, AAD per turn), cascade-deleted with the account and purged by the retention job. The static build runs the same engine in the browser and keeps sessions in `localStorage`. The scripted scene remains for `?s=`/`?all=1` (screenshots, embedded demo).

## Speech input that works when the browser's speech service does not
- **Why**: the Web Speech API is not speech recognition on the device. Chrome and Edge send the audio to Google/Microsoft servers; when those cannot be reached (VPN, firewall, "online speech recognition" off, Brave, Firefox, some WebViews) the recogniser fails with `network` or returns nothing. Vent then looked like it recorded nothing.
- **What**: `useVoiceInput` (src/voice/input.ts) uses live recognition when it works. On `network`, `service-not-allowed`, "sound but no words", or no recogniser at all, it switches (and remembers that, in `localStorage`) to **recording the microphone (MediaRecorder) and writing it out on the device with Whisper** (`Xenova/whisper-base`, int8, via transformers.js + onnxruntime-web WASM, `src/voice/whisper.ts`). No key, no server, no cloud speech service. The recording stays in memory and is discarded after it is written out. Hindi, Marathi, Gujarati and English are passed as the Whisper language.
- **She always confirms**: the written-out words land in the same box; she can fix them, then taps Done; chips, confirm and save are unchanged. Rehearsal uses the same input.
- **Cost / limits (honest)**: the first use downloads about 80 MB of model files from huggingface.co (then cached by the browser) and the WASM runtime is served from our own origin under `/ort/` (so the CSP only adds `script-src 'self' 'wasm-unsafe-eval'` and the Hugging Face hosts in `connect-src`). Transcription runs on the CPU in the browser: expect several seconds for a short clip. whisper-base is much weaker than Google's service for Hindi, Marathi and Gujarati; a larger model (whisper-small, about 250 MB) would be better but is too heavy for a first download. Verified end to end with English speech; Hindi, Marathi and Gujarati quality is NOT verified.
- **Preload**: once recording mode is chosen the model starts downloading immediately so it is usually ready when she stops speaking.
